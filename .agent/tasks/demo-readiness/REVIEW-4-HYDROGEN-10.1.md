### Findings

1. **[MAJOR] Cassandra `activity_by_article_day` loses its synthetic label on account purge**
   - **Location**: [InteractionActivity.php](app/Interaction/InteractionActivity.php#L25-L47), [AccountPurge.php](app/Accounts/AccountPurge.php#L295-L322)
   - **Scenario**: `activity_by_user_month` and `activity_by_article_day` have no `synthetic` or `origin` column (`InteractionActivity::bootstrap()` / `apply()`), so synthetic rows rely solely on the `synthetic-v1-<seed>-<nn>` `user_id` prefix. If a synthetic reader is deleted and purged via `accounts:purge` in a shared demo, `AccountPurge::stepCassandraDelete()` deletes `activity_by_user_month` while `AccountPurge::stepCassandraAnonymize()` (`AccountPurge.php:307`) overwrites `activity_by_article_day.user_id` with `'deleted'` (`self::ANONYMOUS`), stripping the only synthetic marker so those rows become indistinguishable from purged real users' activity.
   - **Fix**: Add a `synthetic boolean` column to both `InteractionActivity` tables populated from `$e['synthetic'] ?? false` on consume/reemit, or capture `synthetic` in `AccountPurge::claim()` context and delete synthetic rows from `activity_by_article_day` instead of anonymizing them to `'deleted'`.

2. **[MINOR] `/admin/users` header count includes synthetic readers while the linked Dashboard stat excludes them**
   - **Location**: [UserController.php](app/Http/Controllers/Admin/UserController.php#L24), [index.blade.php](resources/views/admin/users/index.blade.php#L10), [DashboardController.php](app/Http/Controllers/Admin/DashboardController.php#L31)
   - **Scenario**: `DashboardController::index()` counts `User::where('synthetic', '!=', true)->count()` and links the "Người dùng" stat card directly to `admin.users.index`. `UserController::index()` queries `User::query()->latest()` without filtering `synthetic`, so clicking the dashboard user count opens `/admin/users` showing `Người dùng (real + 16)` in the header total. (Individual synthetic rows are still clearly labelled `Synthetic v1 ...` / `@demo.invalid` so admins can delete them.)
   - **Fix**: Filter `UserController::index()` with `User::where('synthetic', '!=', true)` by default and add an explicit `?synthetic=1` filter/tab for viewing and retiring synthetic readers.

### Angle Checklist Summary
- **(1) Leakage / over-filtering**: Public feeds/cards (`HomeController`, `ArticleCounts` via `MongoCounts::group` with `['synthetic' => ['$ne' => true]]`), `InteractionToggle::run()` (`$model::real()`), live trending (`Trending::forHome()` + `MongoInteractionReplaySource::events()` using `Boost::real()`), Reading Pass quotas (per-subject `u:<id>`), and `DashboardController` / `Admin/ArticleController::show()` all exclude synthetic records without hiding real records lacking `synthetic`. Only `/admin/users` (`UserController::index`) includes synthetic accounts in its listing/total.
- **(2) Label & replay/rebuild/reemit preservation**: MongoDB `synthetic_workloads`, `users`, `bookmarks`, `boosts`, and `article_unlocks` all carry `synthetic: true` (and `synthetic_seed`; `article_unlocks` also sets `origin: 'synthetic'`). `InteractionEvent::membership()` (`InteractionEvent.php:34`), `ReadingPassHistory::event()` (`ReadingPassHistory.php:73`), and `StreamConsumer::replay()` preserve `synthetic` and `synthetic_seed` across `interactions reemit`, `reading-pass reemit`, and DLQ replay; `Trending::apply()` (`Trending.php:72`) routes synthetic events to `interactions:trending:workload:v1:<seed>`. Only Cassandra `InteractionActivity` tables lack a dedicated synthetic column (Finding 1).
- **(3) Determinism**: `SyntheticWorkload::seed()` uses `PcgOneseq128XslRr64($seed)`, URL-sorted `articleIds()`, deterministic `synthetic-v1-<seed>-<nn>` IDs, manifest UTC timestamps, and deterministic UUIDv7 `eventId()` (`SyntheticWorkload.php:136-143`). `UnlockLedger::writeTime()` (`UnlockLedger.php:132-135`) uses `now()` only for `created_at`/`updated_at` (live reservation cleanup age in `CleanupOldGuestUnlocks.php:32`) while `unlocked_at` and Cassandra `occurred_at` use the manifest timestamp.
- **(4) Real-user safety**: `SyntheticWorkload::reader()` (`SyntheticWorkload.php:117-134`) uses `@demo.invalid` emails, `synthetic-v1-*` IDs, `isPurging()` checks, and strict identity/flag assertions before returning a `User`. `Str::random(64)` passwords, `email_verified_at: null`, and `password_reset_requires_verified_email: true` block password login, password reset, and Google OAuth linking (`GoogleAuthController.php:51-54`).
