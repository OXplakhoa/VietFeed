### A. Correctness and standards findings

1. **BLOCKER — Same-second events can permanently deny Pro.** [BillingGateway.php](/home/dolakhoa/code/VietFeed/app/Billing/BillingGateway.php:192) ranks `incomplete` above `active`. If Stripe emits subscription-created `incomplete`, subscription-updated `active`, and Checkout completed in the same second, the incomplete marker wins regardless of delivery order. Even Checkout’s freshly retrieved active subscription gets the lower active rank. All events can receive 200 while the paying user remains free until another later event arrives. Similar ties can keep a recovered subscription `past_due`. **Fix:** reconcile ambiguous ties against current Stripe subscription state using a concurrency-safe ordering strategy; test the full real sequence in both delivery orders.

2. **MAJOR — A retrieved snapshot is ordered by the wrong event time.** [BillingGateway.php](/home/dolakhoa/code/VietFeed/app/Billing/BillingGateway.php:169) retrieves the *current* subscription for Checkout completion, but [assigns it the Checkout event’s creation time](/home/dolakhoa/code/VietFeed/app/Billing/BillingGateway.php:198). For example, delayed Checkout event at T=100 retrieves `active` at T=102, then a delayed subscription event created at T=101 containing `incomplete` overwrites it. **Fix:** do not compare a live snapshot as though it represented the triggering event’s timestamp; serialize reconciliation per subscription and protect it against intervening updates.

3. **MAJOR — The sparse unique customer index can fail on multiple null values.** [The migration](/home/dolakhoa/code/VietFeed/database/migrations/2026_11_17_000001_create_mongodb_billing_indexes.php:14) leaves `stripe_customer_id: null` on users without a nonempty legacy ID, then creates a sparse unique index. MongoDB sparse indexes include fields explicitly set to null, so two such users prevent index creation and block migration. The test covers missing fields and populated legacy IDs, but not multiple explicit nulls. **Fix:** remove null target fields before creating the sparse index, or use an appropriate partial unique index; test multiple null users and reruns.

4. **MAJOR — Customer creation recovery is not durable across changed parameters or Stripe’s idempotency retention.** [BillingGateway.php](/home/dolakhoa/code/VietFeed/app/Billing/BillingGateway.php:28) retries the same key with mutable email and name. If Stripe creates the customer but the response or Mongo write fails, a profile change before retry can make Stripe reject the reused key with different parameters; after key expiry, retry can create an additional customer. [The fake](/home/dolakhoa/code/VietFeed/tests/Doubles/FakeStripeClient.php:17) always returns the same ID and does not exercise either case. **Fix:** persist a durable creation attempt and immutable request parameters, with a reconciliation strategy for an uncertain Stripe result; test the failure and concurrent creation paths.

5. **MINOR — Lease-expiry overlap is not proved by the concurrency test.** [BillingGateway.php](/home/dolakhoa/code/VietFeed/app/Billing/BillingGateway.php:138) lets another worker claim after 60 seconds while the original worker can still execute `apply`; only receipt completion is fenced by the token. The atomic marker prevents a second identical projection update, but a slow Checkout retrieval can still overlap a second retrieval, making the snapshot-ordering defects above observable. [The concurrent test](/home/dolakhoa/code/VietFeed/tests/Feature/StripeBillingTest.php:257) races ordinary workers without forcing expiry or pausing the first worker. **Fix:** add a controlled expired-lease overlap test and fence or serialize projection/reconciliation as part of the ordering fix.

6. **MINOR — Tie tests prove convergence to the chosen rank, not correct Stripe state.** [StripeBillingTest.php](/home/dolakhoa/code/VietFeed/tests/Feature/StripeBillingTest.php:182) asserts that reversed deliveries converge and that the arbitrarily designated last event wins. It omits the common `incomplete → active` sequence and cannot establish chronology from opaque event IDs. **Fix:** assert the expected entitlement and cancellation state for realistic lifecycle sequences, including same-second recovery and cancel-at-period-end changes.
