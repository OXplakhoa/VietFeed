Lesson 1: Why Laravel & Eloquent?

Primary Source: Laravel Official Documentation

Imagine you are standing in front of your lecturer. They look at your project, VietFeed, and ask the inevitable question:

"There are hundreds of frameworks out there. Why did you choose Laravel for a News Aggregator? Why not write it in plain PHP, or use Node.js?"

To defend your project, you need to articulate the strategic advantages of your technology stack. For a news aggregator, Laravel provides three massive architectural benefits.

1. The "Batteries Included" Philosophy

A news aggregator needs user authentication (to save bookmarks and preferences), a database (to store articles), and an admin panel. If you used raw PHP or a micro-framework (like Express in Node.js), you would have to build the login system, session management, and routing from scratch.

Laravel is a Full-Stack MVC Framework. It provides built-in tools like Laravel Breeze for instant authentication, meaning you spent your time building the business logic (the RSS fetching) instead of reinventing the wheel.

2. The Task Scheduler (Cron, Simplified)

A core feature of VietFeed is fetching new articles from sources like VnExpress automatically. Traditionally, developers use messy server-level cron jobs for this.

Laravel provides a built-in Command Scheduler. You define your schedule fluently in PHP code (e.g., $schedule->command('feeds:fetch')->everyThirtyMinutes();). This makes the automated architecture of VietFeed explicit, version-controlled, and easy to explain.

3. Eloquent ORM: Active Record pattern

When fetching hundreds of RSS feeds, you must avoid saving duplicate articles into the database.

Instead of writing raw, complex SQL queries to check if an article exists before inserting it, Laravel uses Eloquent ORM (Object-Relational Mapper). Eloquent maps database tables to PHP Classes.

You can simply write:

Article::updateOrCreate(['original_url' => $link], [...])

This elegantly checks if an article with that URL exists, and if not, creates it. It turns complex SQL deduplication into a single, highly readable line of code.
